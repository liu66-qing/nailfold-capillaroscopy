# EXP-B 归档：视频时序信息能否预测 flow_state

**状态**：已终止（2 / 3 臂完成，结论已确定）
**日期**：2026-09-11
**脚本**：`exp_b_video_flow.py`
**产物**：`/root/nailfold/artifacts/experiments/exp_b_video_flow/`
（`S_static_oof.csv`、`T_video_oof.csv`、`summary.json`、`video_frame_index.csv`）

## 问题

静态单帧图像原则上不含血流速度信息。`flow_state`（流态）被先验归入
NO_SIGNAL 字段组。本实验直接检验：**引入视频时序帧能否让冻结的
DINOv2 学到 flow_state？**

## 设计（自对照）

三臂共用**同一批 91 个 case**、同一目标、同一网络、同一 CV 划分，
唯一变量是输入帧的来源。这样可排除队列差异、类别分布差异等混淆。

- 队列：93 个有视频的 dev case，剔除 2 个稀有类样本后 91 个
- 类别（保留 4 类，`MIN_CLASS=5`，稀有类丢弃而非合并）：
  粒流 39 / 粒线流 29 / 线粒流 12 / 粒缓流 11
- 每视频抽 8 帧（`N_PER_VIDEO=8`），ffmpeg 均匀采样
- 3 seeds × 5 folds，`development_fold`，test=fold, val=(fold+1)%5

**重要队列偏倚（已知并记录）**：视频是选择性保存的。这 91 个 case 的
等级构成为 重度 47 / 中度 42 / 轻度 1 / 大致正常 1 —— 阴性类被系统性排除。
这正是本实验只能回答局部问题、不能外推到全体的原因。

## 结论

1. **静态图无法预测 flow_state**：BA 0.192 < 随机 0.250，
   acc 0.275 < 多数类 0.429。独立验证了 NO_SIGNAL 分组是正确的。
2. **加视频没有救回来**：BA 仅从 0.192 升到 0.204（+0.012），
   仍显著低于随机。在当前方法（冻结 DINOv2 + 帧级特征聚合）下，
   时序信息没有被有效利用。
3. 这是一个干净的**自对照负结果**：不是"视频价值低"，而是当前
   方法下**根本学不到**。

## 为何终止 ST_both

- 前两臂已确定结论：两者都在随机水平以下，合并输入不可能反转判断。
- 天花板分析独立表明：不可观测字段那一半即使做到完美，
  total_score MAE 也只有 3.139，**比当前 2.737 更差**。
  所以视频这条线即使成功也不构成提升 total_score 的路径。
- 服务器 CPU 负载达 54（其他项目抢占），ST_both（2377 帧，最大臂）
  几乎停滞，占用的资源应让给有 0.93 MAE 确定空间的单字段专项实验。
- 用户于 2026-09-11 明确批准终止。

## 若要重启此方向，需要先改变的前提

以下任一条成立时，重跑才有意义（否则预期仍是负结果）：

- 换用真正的时序模型（光流、帧差、时序注意力），而非帧级特征平均
- 补齐阴性类视频，消除队列的选择性保存偏倚
- `flow_speed_um_s` 字段被实际填充（当前覆盖率 0.00，全空）
- 有证据表明 flow_state 的报告标签本身可靠（当前无重复标注，无法测）
