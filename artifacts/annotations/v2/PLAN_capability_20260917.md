## 1. 诊断：为什么现在不能上线

不是"模型不够强"，是三个不同性质的问题叠在一起。混为一谈就会一直投错方向。

### 问题 A：模型侧已到顶（不要再投）

三条路径已用实验封闭，都是配对比较、非单点：

| 路径 | 实测 | 结论 |
|---|---|---|
| LoRA r4/r8/r16 × 5 seed | 配对增益 −0.0017 / −0.0077 / **−0.0195**（r4 CI 上界 −0.0018） | 关闭 |
| 解冻 / 损失平衡 / 视频 | 见 `nailfold-closed-paths` | 关闭 |
| 表格学习 / 冻结特征 MIL | 见 `nailfold-method-ceilings` | 关闭 |

字段级 seed 波动 0.027~0.081 → **任何 <0.08 的字段级改进都在噪声内**。
继续调模型是在噪声里挑数字。

### 问题 B：标签粒度与噪声天花板（决定上限在哪）

- 直径标签只有 3~5 档，档距 < 模型 MAE → 三个管径字段全部无效（delta +0.024~+0.079，CI 全含 0）。
- 文献专家间一致性：可判读性 ICC **0.14**、密度 ICC 0.64、Maricq κ **0.47**、Cutolo κ **0.49**。
- 我们的 0.77 准确率**可能已接近标签噪声上限**。
- 本地已有证据：`exp_f_label_noise/direction.json` 显示 66 例存在字段↔叙述冲突，
  集中在 papilla(23) / exudation(20) / SVP(19)，且被标记样本的 OCR 置信度**更高**
  （papilla Cliff's δ = +0.365）→ **不是 OCR 错，是判读本身分歧**。

含义：不知道天花板在哪，就无法判断 0.77 是"还差很多"还是"已经到顶"。
**这是必须先测的量，不是可选项。**

### 问题 C：真正的上线门槛（与模型精度几乎无关）

- 监管无 sens/spec/AUC 数值下限（FDA/NMPA/EU MDR 均无；PMDA 已批 151 个 SaMD，
  standalone 敏感度跨度 67.7%~100%）。
- 真门槛是 **低患病率 PPV**：5% 患病率下 clarity PPV **0.150**、blood_color 0.144、
  exudation 0.129、SVP 0.116 → 报 100 个阳性约 85 个是假阳性。
- **外部验证 = 0**。全部数字来自同一批 186 例、同一台设备、同一套标注。
  locked-47 是同批留出，**不构成外部验证**。
- 对照已过 FDA 的 ECG-AI：4 中心 13,960 例、AUROC 0.92、sens 84.5%、spec 83.6%，
  各项都强于我们，7.9% 患病率下 PPV 仍只有 30.5% → 作者定位 **rule-out**。

含义：**把 0.77 提到 0.85 也不能上线；把 PPV 工程做对、拿到第二中心数据才能上线。**
我们唯一站得住的定位与 ECG-AI 相同：NPV 0.98~0.99，阴性说"本次未见异常"，
阳性只能说"建议进一步检查"。

## 2. 策略：把"提升模型能力"翻译成四个可交付工程

"能力"对产品来说不是 accuracy 数字，是**在真实患病率下有多少可用输出**。
按此定义，下面四项每一项都直接增加可用输出，且都不依赖已封闭的模型侧路径。

优先级按"单位投入的上线贡献"排，不按技术难度。

---

### 工程 1：弃答 + 低患病率阈值工程（最高回报，纯 CPU，1~2 天）

**这是把现有模型变成可上线产品的唯一一步，不需要任何新数据。**

现状问题：所有工作点都选在"最大化准确率"，这是错的目标函数。
产品要的是"在可接受的假阳性率下，覆盖尽可能多的病例；不确定的交给人"。

做法：
1. 对 5 个可用字段，从 OOF 预测重建 risk score，**病例级**。
2. 扫覆盖率 100%→30%，在每个覆盖率下用**内层验证折**选阈值（不看测试折），
   报告 accuracy / sens / spec / **PPV@5% / PPV@10% / NPV@5%** + 病例级 bootstrap CI。
3. 输出"覆盖率–PPV"曲线，选择满足 **NPV ≥ 0.98 且弃答率 ≤ 40%** 的工作点。
4. 双阈值设计：低于 t_low 判"未见异常"，高于 t_high 判"建议进一步检查"，
   中间 **弃答**（不输出）。

已有线索：旧协议下 afferent 60% 覆盖 delta +0.170→+0.212，
loop 40% 覆盖 +0.205→+0.254。**必须按现口径重测**（旧数字含协议偏差）。

成功判据（预先声明）：至少 3 个字段能在弃答率 ≤40% 下达到 NPV ≥0.98 且
PPV@10% ≥0.30（对齐 ECG-AI 的 0.305）。
失败判据：所有字段在任何覆盖率下 PPV@10% <0.25 → 单字段路线不成立，
转工程 2 的联合筛查。

复现：`scripts/` 新增 `engineer_operating_point.py`，输出
`artifacts/experiments/operating_point_20260917/`。

### 工程 2：从"字段级预测"改为"单一 rule-out 筛查器"（高回报，纯 CPU，2~3 天）

现状问题：产品把 20 个字段各自输出，其中 15 个不能上线，用户看到的是一堆
不可靠字段。而 `overall_assessment` 二分类 delta **−0.103**（CI 上界 −0.043，
显著为负）—— 直接学"整体是否异常"是失败的，原因是 90.9% 样本为异常，
特异度塌到 0.062。

关键洞察：**不要学"是否异常"，要学"是否正常"。**
正常类只占 9.1%（17/186），把它作为正类会极度不平衡；但 rule-out 产品需要的
恰好是"高置信度识别正常人"，这是一个**高特异度、低覆盖**任务，
和"高准确率多分类"完全不同的目标。

做法：
1. 用 5 个已验证可用字段的 OOF 概率作为特征（**只用可用字段，不喂噪声字段**），
   拼上 geometry，训练一个病例级 rule-out 分类器。
2. 目标函数直接是 **在 spec ≥0.95 处的 sensitivity**，不是 accuracy。
3. 与两个零成本基线配对比较：(a) 永远说"异常"；(b) 5 字段全部正常则说正常
   （规则法，无模型）。**模型必须赢规则法才有意义。**
4. 病例级 bootstrap 2000 次，报 delta CI。

成功判据：在 spec ≥0.95 处 sens ≥0.40，且**配对优于规则法** CI 下界 >0。
失败判据：赢不过规则法 → 直接交付规则法（更简单、可解释、可上线），
不上模型。这个失败也是**有价值的交付**。

---

### 工程 3：标签一致性测量（决定还有多少空间，必须做）

用户已否决双人全量重标。但**不测就是盲目优化** —— 这是第 1 节问题 B。

做法（低成本版，不需要第二位医生）：
1. **已授权的 AI 辅助标注池**（129 图 / 49 病例，2026-09-17 授权）用于
   `crossing` / `malformation` 两个字段的弱监督一致性抽测。
   注意：49 病例是现有 186 的子集，**不增加病人**，CI 仍 ±0.15 →
   这是**可行性闸门，不是选择实验**。
2. **叙述–字段一致性**已有 66 例冲突（`exp_f_label_noise`），
   把它当作"标签噪声下界估计"：papilla/exudation/SVP 至少 10~12% 的标签存在分歧。
3. 据此计算**噪声修正上限**：若标签噪声率 p，则准确率上限约 1−p。
   papilla p≈0.124(23/185) → 上限 ≈0.876，实测 0.789，**还有 0.087 空间**；
   exudation p≈0.109 → 上限 ≈0.891，实测 0.743，**还有 0.148 空间**。
4. 对分歧集中的三个字段，做**去噪重训**：剔除冲突病例后重训，
   看 delta 是否上升。若上升 → 噪声是瓶颈，值得投入标注治理；
   若不变 → 噪声不是瓶颈，模型侧确实到顶。

成功判据：剔除冲突病例后至少 2 个字段 delta 提升 >0.08（超过 seed 噪声）。
失败判据：三个字段提升均 <0.08 → **标签治理不是瓶颈，停止该方向**，
把资源全部转向工程 4。

这一步的价值不在提升数字，在于**它能证伪"继续优化还有回报"这个假设**。

### 工程 4：外部验证数据（唯一绕不过的门槛，需要用户决策）

第 1 节问题 C：外部验证为零，这是最大缺口，**重于任何模型改进**。

现实约束：这不是我能靠算力解决的问题，需要第二中心/第二台设备的数据。
GPU 再多也生不出外部数据。

我能做的准备工作（不需要新数据，可立即做）：
1. **设备/批次敏感性分析**：用 `exp_a_label_audit/case_date_groups.csv` 的
   日期分组做 leave-one-date-group-out 评估。若跨日期组性能掉得厉害，
   说明模型学了批次特征，外部验证一定失败 —— **这是外部验证的廉价预演**。
2. **域偏移探针**：已有 `data/domain_adapted`（424M），
   测模型在 resize/亮度/对比度扰动下的稳定性。
3. 冻结一份**外部验证协议**（样本量、终点、统计方法），
   等数据到位可直接执行，不用临时设计。

成功判据（针对 1）：跨日期组性能下降 <0.08 → 模型没学批次特征，外部验证有希望。
失败判据：下降 >0.15 → 当前模型**几乎肯定过不了外部验证**，
应先解决域鲁棒性再谈上线。

## 3. 2 卡 4090 用来做什么

诚实说：**上面四项工程，1/2/3 都是 CPU 任务**，GPU 派不上用场。
LoRA 已封闭，不该再跑。所以 GPU 的正当用途只有两个：

| 用途 | 说明 | 优先级 |
|---|---|---|
| **重跑特征提取** | 只有 1708 帧被索引，磁盘上另有 **499 张 CAPorg 图未入索引**（62 个病例目录）+ 1952 视频帧。先查这 499 张属于哪些病例、为何被排除；若属 dev 病例且质量合格，重提特征可把 1708→2207 帧（+29%），病例数不变但每病例帧数中位 9→11 | 中 |
| **分割/几何重算** | `Model/DINOv2-base` 已在两端；若工程 3 判定标签噪声不是瓶颈，可用 GPU 重算更细的几何量（不是新模型，是更准的测量），绕开"3~5 档标签"的粒度限制 | 低，依赖工程 3 结果 |

**不做**：LoRA 超参、更大模型、集成（实测增益 −0.020~+0.003、无、+0.003）。
2 卡不改变这些结论 —— 它们不是算力受限，是方法到顶。

## 4. 执行顺序与判据汇总

```
工程 1（弃答+阈值，CPU，1~2 天）  ← 立即开始，最高回报
      ↓ 失败则并入工程 2
工程 2（rule-out 筛查器，CPU，2~3 天）
      ↓ 与规则法配对比较，可能交付规则法
工程 3（标签噪声上限，CPU，2 天）  ← 证伪"还有空间"这个假设
      ↓ 若判定噪声不是瓶颈
工程 4-准备（日期组敏感性，CPU，1 天）  ← 外部验证的廉价预演
      ↓
工程 4-正式（需第二中心数据）  ← 用户决策，非技术问题
```

全程硬约束（继续有效）：
- **locked-47 不训练、不选择、不评估、不外发**，每脚本断言 `locked_cases_seen: 0`。
  locked 已被历史实验污染，**只允许一次最终评估**，且按**病例级**排除衍生物。
- 只用 `development_fold`（NaN = locked47）划分；用 `split` 列会得出反向结论。
- 所有 OOF 病例级唯一，`unique key = exam_case_id + field`，不得有帧重复记录。
- 配置选择只在内层验证折，**不看测试折**。
- 每个结论附：可复现命令、文件路径、样本量、hash、limitations。
- 开发集结果**永不**作为产品能力汇报。
- 原始临床标签 / 人工标注 / AI 辅助标注三者分离，**均不作金标准**。
- 新输出写 `/root/autodl-tmp/` 下（`/` 只剩 3.7G）。

## 5. 预期终局（诚实版）

做完 1~3，最可能的产品形态是：

- **一个 rule-out 筛查输出**：阴性说"本次未见异常"（NPV 0.98~0.99），
  阳性说"建议进一步检查"，中间弃答。
- **5 个字段的二分类辅助信息**，标注为"辅助参考，非诊断"。
- 15 个字段**不输出**（9 个显著劣于众数规则，6 个与众数不可区分）。
- 仍**不能声称**：微米级精度、档位判读（几个加号/几排静脉丛）、诊断结论。
- 上线仍**缺**外部验证 —— 这是工程 4，非算力可解。

如果目标是"现在就上线"，那么可交付的只有 rule-out + 5 字段辅助 + 明确免责，
且必须先完成工程 1 拿到 PPV 工作点。**这不是保守，这是当前证据支持的上限。**
