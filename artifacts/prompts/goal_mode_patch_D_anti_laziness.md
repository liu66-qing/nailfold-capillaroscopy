# 补丁 D：反偷懒约束与执行验证

> 本补丁针对 v2 失败报告中暴露的问题：E1-E9 均未进行实质训练，辅助数据未被使用。

## 核心原则：做了才算，没跑代码等于没做

一个实验"完成"的最低标准不是写了报告，而是：
1. 存在可执行的 `.py` 训练脚本，且脚本中包含数据加载、模型定义、训练循环和评测输出
2. 存在训练日志（loss 曲线、epoch 数、GPU 使用时间）
3. 存在新的模型 checkpoint 文件（不是 v1 的已有 checkpoint）
4. 存在新的 OOF 预测文件（不是 v1 的已有预测加减某个后处理）
5. 以上文件的创建时间在本轮实验周期内

**在已有 OOF 预测上改阈值、换聚合函数、拼已有特征重跑 ExtraTrees，都不算"新实验"。** 这些是 v1 分析的一部分，不是 v2 模型开发。

## 辅助数据必须被使用

以下数据已通过治理审计，必须在实验中实际使用（不是"分析后声称不能用"）：

### 2,332 对已确认分割图像/mask
- **用途 1**：训练或微调一个分割模型（U-Net/SegFormer），提取更好的血管特征
- **用途 2**：从 mask 提取帧级结构特征（面积、周长、骨架长度、分支数、宽度分布）作为新输入
- **用途 3**：训练分割质量评估模型，用于帧质量门控
- **locked 隔离方案**：这些分割数据的匿名源组尚未完全映射到 exam_case_id。解决方式不是"不用"，而是：
  - 方案 A：仅用于预训练特征提取器（不参与下游分类器选择），然后冻结
  - 方案 B：用交叉排除法——如果某个源组可能对应 locked 病例，在该 fold 中排除该源组
  - 方案 C：先完成源组到 exam_case_id 的映射（这是一个可执行的数据工程任务，不是不可能的任务）
  - **不接受"因为无法 100% 排除重叠所以完全不用"。** 选择上述方案之一执行。

### 89 张检测辅助图像
- **用途**：训练或校准检测模型，用检测结果作为帧级特征输入
- 89 张不够单独训练？可以和 582 张分类图一起用，或作为检测预训练的补充

### 治理后的 XML/YOLO 标注
- **用途**：训练检测模型提取帧级目标特征（每帧的检测框数量、置信度分布、类别分布）

## 禁止的借口模式

以下论证模式被识别为逃避执行的信号，不接受：
1. ❌ "数据不能用因为无法 100% 证明与 locked 无重叠" → ✅ 使用交叉排除或预训练冻结方案
2. ❌ "分割 mask 不是临床金标准所以不能用" → ✅ 没人要求用 mask 当标签，用它提取特征
3. ❌ "中间特征有生成协议问题" → ✅ 重新在每个 fold 内从头提取，而不是用预计算的
4. ❌ "89 张太少不能训练" → ✅ 用于预训练/微调/检测校准，不是要求单独训练最终模型
5. ❌ "该实验的前置条件不满足所以 HOLD" → ✅ 前置条件是你自己要创造的，不是等别人给的
6. ❌ "全字段闸门无法同时满足" → ✅ 按字段独立评估，单字段提升就值得保留

## 修订后的闸门规则

旧规则要求"全部字段同时满足"，这导致任何单字段退化就判全部失败。修订为：

**字段级闸门**（每个字段独立判断）：
- 该字段 BA 或 macro-F1 ≥ v1 **且** ≥ 3/5 folds 获益 **且** 少数类召回不下降 > 2pp → PASS
- 其他字段无显著退化（BA 下降 ≤ 3pp）→ 无副作用

**模型级组装**：
- 通过字段级闸门的字段使用新模型
- 未通过的字段保留 v1
- 允许混合模型（字段 A 用 v2，字段 B 保留 v1）

这样即使只有 1 个字段提升，也是有价值的交付。

## 强制执行检查点

在以下时间点，暂停并自检：

### 24 小时检查点
必须已经完成：
- [ ] 至少 1 个分割模型在 2,332 对数据上开始训练

- [ ] 至少 1 个 .py 训练脚本存在于 experiments/ 目录

- [ ] 训练日志和 GPU 使用记录

### 72 小时检查点
必须已经完成：
- [ ] 所有候选方向至少跑了 1 个实验（有脚本+日志+OOF）
- [ ] 逐字段的 v1 vs 候选对比表
- [ ] 决定哪些字段采用新模型、哪些保留 v1

## 关于"不可能提升"的正确判断标准

只有在以下情况下才能声称某字段"不可能提升"：
1. 已经用新特征（分割/检测/骨架）替换了原始输入，BA 仍无变化
2. 已经尝试了至少 3 种不同的模型架构（不只是 ExtraTrees）
3. 已经用 MIL/attention pooling 替换了 mean pooling，BA 仍无变化
4. 少数类支持 < 5 且已尝试过采样后仍无效
5. 以上每一条都有训练日志和 OOF 文件作为证据

"前置条件不满足" 不是 "不可能提升" 的有效理由。前置条件是你要创造的。
